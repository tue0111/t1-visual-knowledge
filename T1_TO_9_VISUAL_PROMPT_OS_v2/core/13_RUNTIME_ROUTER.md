# 13 RUNTIME ROUTER AND USAGE POLICY

This is the task-routing policy, not a replacement for visual laws. Current request, assigned reference and latest correction remain above every stored default. Apply core/00_PROJECT_CONTRACT.md; consult the full relevant engine whenever its detail changes a decision.

## 1. Choose the smallest sufficient route

Classify delivery intent separately from work depth. Prompt-authoring returns text; image generation/editing requires a real available tool and the required input. Analysis-only stays analysis-only. Do not render to test a prompt-only request.

| Mode | Trigger | Additional reads and work |
|---|---|---|
| PATCH | An existing prompt/output is available and the request is a bounded correction, faithful translation or selected-frame extraction | Use current artifact + preserve/change/uncertain + one acceptance check. Keep family, identity and successful layers. Read only the module governing the changed dimension; do not redo family selection, concepts, brief worksheets or the full audit. |
| STANDARD | A sufficiently clear new brief fits an existing family | Read core/01_CORE_LAWS.md, core/03_PROMPT_COMPILER.md and library/13_FAMILY_REGISTRY.md, then exactly the selected family/kernel and necessary task modifiers. Director works directly. |
| DEEP | Conflicting/multiple reference roles, unresolved complex diagnosis, research, new family/fusion, or a structurally complex album | Add core/02_DECISION_WORKFLOW.md and core/09_VALIDATOR_AND_DEBUGGER.md plus relevant engines. Use Analyst only for a concrete unresolved context/evidence question. |

PATCH requires access to the actual artifact; memory of its title is insufficient. If absent, retrieve that artifact once or ask for it. If a correction changes the underlying visual system, escalate to STANDARD/DEEP with a short reason. A simple established-family album is STANDARD plus core/08_ALBUM_ENGINE.md; an album does not automatically require Analyst. Do not birth/register a new family for a one-off patch.

## 2. Minimal preflight and escalation

Before delivery check: current overrides; unchanged identity/pose/crop/world outside allowed dependent changes; the requested change; contradictory positive/negative instructions; requested language, section format, frame count and text/logo exceptions; truthful tool/result status. For new designs also check hierarchy and relevant camera/light/material agreement using the selected laws and family.

If a check is unclear or fails, read the responsible engine or core/09 and repair that layer. A short preflight must not label uninspected visual output as verified. Full aesthetic/fusion/album audits remain available for DEEP or when explicitly requested.

## 3. Bounded Analyst use

Explicit reverse-match work uses the scoped REVERSE_IMAGE_PROMPT_LOOP_SLIM.md under project Knowledge_Mindset (package canonical/Knowledge_Mindset). Preserve its one Final per user message, slim REVERSE_LOOP handoff, user-driven scored rounds and no extra pack/final-check rules. Its scoped limits take precedence over generic loop defaults below. Do not turn a reverse prompt request into automatic image-generation retries. VOXCAT_CREATIVE_CHAIN.md applies only when preserving that revision chain. These files are on-demand, never a normal startup requirement.

Director may finish PATCH and STANDARD without Analyst. For DEEP, call Analyst only when independent reference/context/research analysis can resolve a named uncertainty; otherwise Director continues with the relevant engines. Compiler and QA remain responsibilities, not extra Bots.

Default budget per task: one Analyst request and at most one focused follow-up. Send only current brief, assigned reference IDs, the question and relevant constraints. Return the required typed handoff as NON_FINAL_ADVICE with actionable observations, inferences, uncertainty, evidence links and acceptance checks; avoid reproducing source documents or the Director prompt. Aim for a compact handoff (about 600 words or less); expand only when essential evidence would be lost. Do not invent a handoff when Analyst was skipped.

On budget exhaustion, Director proceeds if evidence is sufficient; otherwise identifies the exact unresolved question. Do not bounce the same question between Bots. User-requested deeper work can extend the budget explicitly within the current task.

## 4. Context reuse and retrieval

Verify package integrity at installation/release change, not on every creative request. Pin one release for the current task; adopt a new release at a task boundary after verification. Never mix source/package snapshots.

Reuse a previously read module only when its content is still available in the current context or a verified cache keyed by release ID + relative path + SHA-256. Maintain a compact task state: artifact/reference IDs, current overrides, family, preserve/change/uncertain, last accepted result and next check. Invalidate task decisions when references or corrections change; invalidate cached module content when release/hash changes. A cache entry or memory summary without accessible content is not proof of retrieval or persistence.

Read exact routed files/sections. Do not scan the repository, all families, all schemas, all generator profiles, raw research or all examples. Deduplicate paths within a task; reread only if content is absent, truncated, changed or required detail is missing. A cold session reads the bootstrap/profile and relevant modules again; do not claim cross-session cache support without evidence. Do not start polling, healthchecks or background research.

## 5. Output, retries and measurement

Keep full typed records for auditable DEEP/generation/release work when requested or supported. Routine prompt-only tasks need a compact task state and preflight; user-facing output is the requested prompt, not a packet/settings/checksum report. IMAGE_GENERATE/IMAGE_EDIT returns the real result plus only material limitations. Keep internal records outside generated prompts.

Default maximum is two diagnosed corrective retries per output, with a new causal hypothesis each time; stop earlier on missing capability, repeated identical failure or sufficient acceptance. A timeout with unknown completion is not permission to issue a duplicate image call: inspect result/job state first when available. Preserve explicit user budgets and requested album size. Do not spend generation calls validating prompt-only tasks.

For usage evaluation record mode, unique files/bytes read, actual tool/Analyst calls, elapsed time, available token counters, retries and acceptance result. Missing token counters are UNKNOWN. Compare the same task set and quality checks before/after. File bytes or fewer reads are not a measured quota/token saving.
