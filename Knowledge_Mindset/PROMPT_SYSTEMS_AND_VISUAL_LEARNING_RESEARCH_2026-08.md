# 1. What is genuinely new to this workspace

The project already has family routing, hard/soft/open decisions, one-axis retries, scoped lesson promotion, and progressive loading. The external material adds five sharper distinctions:

1. **A reusable skill stores a judgment process, not a long prompt.** Its value is boundary, routing, parameter policy, conflict handling, audit, and repair location.
2. **Visual ability is diagnosis, not prompt collecting.** The durable loop is to see what the model understood, name what should stay, name what should change, and choose the next smallest instruction.
3. **Prompt information is not measured by character count.** A short production-type term can activate a dense bundle of visual conventions; a long string of evaluative adjectives can still be structurally empty.
4. **Short modules work when they own different jobs.** Capture language, layout language, project purpose, and subject identity can cooperate. Several labels fighting over the same dimension create compromise or drift.
5. **One attractive output proves potential, not stability.** Compressed prompts and candidate families require repeated sampling, cross-subject tests, and boundary cases before promotion.

# 2. Rule-routed visual skills

## 2.1 Begin with a bounded repeated problem

Do not start from “a universal visual skill.” Write six to ten realistic requests first, then infer the shared boundary.

Useful request classes include:

- create from a one-line idea;
- create from complete parameters;
- preserve an existing design while improving a few axes;
- diagnose a named failure;
- derive several directions inside one visual system;
- handle a boundary ratio, scale, or scene type.

The boundary must say both what the skill does and what it does not do. Environment direction, character portraiture, story writing, and video cinematography are different problem domains even when they share a genre.

## 2.2 Use shared laws plus orthogonal routes

The efficient architecture is:

~~~text
shared laws
+ scene route
+ style route
+ optional named exception route
→ one workflow
→ route-aware audit
~~~

Scene and style routes should combine only when they control different decisions. Do not copy four full prompts for two scene routes multiplied by two style routes. Keep selection logic in the entrypoint and load detailed references only after the route is known.

An exceptional route with a substantially different worldview should be explicit opt-in. It should not silently contaminate default routes.

## 2.3 Convert taste into observable relations

Words such as “premium,” “epic,” “cinematic,” and “airy” are goals, not tests. Rewrite them as relationships a reviewer can pass or fail:

- subject-to-frame ratio;
- number and order of depth layers;
- size relationships between people, doors, columns, platforms, and the frame;
- allocated breathing-space range and what occupies it;
- source, receiver, and shadow relationship;
- material behavior under light;
- allowed and forbidden spatial devices.

A rule belongs in a reusable skill only when it can answer: **what evidence would show that this passed?**

## 2.4 Lock parameters, defaults, and conflicts separately

Treat the skill as a function with explicit parameters:

~~~yaml
frame:
scene_route:
style_route:
camera_intent:
subject_role:
palette_strategy:
light:
material:
atmosphere:
output_mode:
~~~

- A user value is a hard lock unless it conflicts with safety or an impossible enum.
- A default fills only an unspecified field.
- Unsupported values are reported, not silently approximated.
- Related concepts remain independent: distance is not camera height; wide shot is not overhead; low angle is not close distance.
- Conflict policy decides which dimension wins before prose is generated.

## 2.5 Fix workflow and test the repair location

A visual skill's entrypoint should mainly define action order:

1. lock user values and defaults;
2. choose the applicable routes;
3. name one composition or perception mechanism;
4. allocate space, scale evidence, camera, light, palette, and material;
5. compile the requested output mode;
6. audit shared laws and route-specific laws separately.

Test at least:

- one-line creation;
- full-parameter creation;
- preserve-and-improve editing;
- explicit failure diagnosis;
- vertical and ultrawide boundaries;
- structurally different subjects or scenes.

When a test fails, locate the cause as shared law, route law, parameter conflict, compiler, or audit. Repair that layer rather than adding a sentence only to the failed example.

# 3. Visual literacy as the durable skill

## 3.1 Teach from the learner's actual starting point

Modern image workflows often begin with conversational language and a reference image, not a table of sampling parameters. A useful learning path therefore begins with:

1. what an image model and a prompt do;
2. why repeated generations vary;
3. how to write the first concrete description;
4. how to inspect the first result;
5. how to decide the next sentence.

Technical parameters remain relevant when the selected tool exposes them, but they should appear when they solve a visible problem rather than as an entry tax.

## 3.2 Replace binary taste with a diagnosis ledger

After every generation, write three fields before revising:

~~~yaml
preserve:
change:
uncertain:
~~~

- **Preserve** names successful identity, hierarchy, composition, light, material, or mood layers.
- **Change** names one observable failure and one target state.
- **Uncertain** separates sampling variance, ambiguous instruction, reference contamination, and possible tool mismatch.

This converts “good/bad” or “something feels wrong” into an actionable next turn.

## 3.3 Build vocabulary when the problem appears

Introduce composition when subjects collapse to the center. Introduce material behavior when silk becomes plastic. Introduce reference jurisdiction when face, wardrobe, and style bleed together. Introduce series design when a second and third image cannot preserve identity.

The order follows visible failure:

~~~text
subject + action + relationship
→ view position + composition
→ light + color + material
→ medium + style system
→ reference roles
→ identity continuity
→ series invariants and degrees of freedom
~~~

## 3.4 Failure sequences are stronger evidence than galleries

A successful image proves that a direction can work. A failure-to-repair sequence reveals:

- which layer failed;
- which phrase or reference likely triggered it;
- which axis changed;
- which successful layers survived;
- whether the correction reproduced.

For identity work, distinguish permanent identity information from shot-local makeup, wardrobe, pose, and lighting. More references are not automatically more stable; each reference needs a named authority dimension.

For a series, declare both invariants and legal variation. A group of attractive images is not a coherent series unless a stable relationship persists while selected axes rotate.

# 4. Information-dense prompt modules

## 4.1 Evaluate information structure, not length

There are two very different kinds of short language:

- **Evaluative adjectives:** beautiful, high-end, atmospheric, stunning. These judge an outcome but do not select a production method.
- **Production-type terms:** editorial portrait, minimal fashion cover, independent art-project key visual. These may carry mature conventions about capture, styling, layout, hierarchy, typography, and use.

A prompt can be long and thin by repeating one evaluation dimension. It can be short and dense by selecting several compatible production systems.

## 4.2 Give every module one jurisdiction

A useful module map is:

| Role | Question it answers | Example class |
|---|---|---|
| Capture / medium | How is the subject photographed or rendered? | editorial portrait |
| Layout / order | How is the image organized after capture? | minimal fashion cover |
| Purpose / concept | Why does this asset exist and what identity must it express? | independent art-project key visual |
| Subject identity | Around whom must color, symbol, silhouette, and tone reorganize? | a named or referenced character |

The separator between modules has no special power. Compatibility comes from non-overlapping jobs and a common direction.

If two modules both own layout, surface, or era, assign an unequal hierarchy or remove one. If a term cannot be expanded into visible decisions, treat it as mood, not a load-bearing module.

## 4.3 Choose a compression mode deliberately

| Mode | Form | Benefit | Risk | Required follow-up |
|---|---|---|---|---|
| Discovery | one dense production type + subject | fast surprise and model initiative | high sampling variance | generate a small probe set |
| Direction | one compatible module per role + key constraints | clearer authorship with retained emergence | hidden defaults remain | audit role outputs |
| Production | expand load-bearing labels into camera, layout, identity, light, material, and keep/change locks | repeatability and portability | more context and possible over-control | remove redundant clauses |

Use compressed discovery to find a direction. Once a result wins, decode the decisions that matter and lock them for production. Do not assume a model-specific dense term will transfer unchanged across generators.

## 4.4 Validate compressed prompts as hypotheses

A short prompt is stable only after tests such as:

- several samples with the same subject;
- several distinct subjects with the same module stack;
- more than one aspect ratio;
- a preserve-one/change-one edit;
- a test with typography enabled and another with typography reserved for post;
- inspection for identity drift, repeated attractor, unwanted logos, and model-invented symbols.

One exceptional image demonstrates potential. Reproduction demonstrates a direction. Cross-subject reproduction begins to justify a reusable route.

## 4.5 GPT Image 2 scope note

The VoxCat article's interpretation is plausible for GPT Image 2 because OpenAI describes stronger layout, text rendering, instruction following, style control, real-world knowledge, and production-oriented image workflows. Official OpenAI guidance also states that effective image prompts can be short, while recommending explicit purpose, subject, action, setting, style, and constraints plus small targeted revisions.

This does **not** establish a universal internal mechanism or guarantee that one label will always unfold the same way. “Photographer,” “designer,” and “art director” are useful functional metaphors for observed output roles, not claims about model architecture.

The attached example set supports coordinated portrait styling, color, crop, and character cues. It is weaker evidence for reliable long-form typography or complete magazine systems; those require separate tests.

# 5. Candidate grammar: xianxia environments and eastern sky megastructures

## 5.1 Scope boundary

This is a candidate **environment-direction** grammar for landmarks, inhabited celestial settlements, and monumental eastern architecture. It is not a branch of the current `FAMILY_XIANXIA_EDITORIAL.md`, whose anchor is a real adult fashion subject.

Do not register a new canonical family until three structurally different calibration renders survive review.

## 5.2 Candidate shared rules

- Supply at least four observable scale proofs rather than only “grand” or “epic.”
- Build five spatial roles: foreground threshold, human-bearing plane, ruling mass, subordinate space, and horizon terminus.
- Reserve roughly 40–60% content-bearing air: sky breaks, water, courtyard, portal void, space below bridges, cloud gaps, or distant light. It must support scale and depth, not become blank gray fog.
- Establish load-bearing structure—columns, beams, bases, platforms, roof overhangs—before ornament.
- Keep environmental adults very small, approximately 1–4% of frame height, usually back or rear three-quarter, when people serve as scale evidence rather than portrait subjects.
- Hair, sleeves, trailing fabric, flags, trees, mist, and particles should agree on one wind field.
- Treat open platform or bridge edges as a fictional compositional device, not a universal claim about historical architecture or real-world safety. Use it only when the current scene intentionally needs exposed scale and the brief permits it.

## 5.3 Orthogonal candidate routes

Scene route:

- **single celestial landmark** — one gate, tree, altar, observatory, archive, island, or pavilion;
- **inhabited divine settlement** — primary and subordinate districts, streets, courtyards, transport, cloud harbor, water system, and distant habitation.

Style route:

- **luminous clear xianxia** — bright but zoned color, transparent atmosphere, precise materials, no global orange-gold cast;
- **eastern sky megastructure** — low viewpoint, cropped or occluded giant structure, threshold reveal, overhead pressure, discontinuous scale relationships.

A quieter grand-realm canon may remain explicit opt-in if it changes the worldview enough to require low clouds, few distant anchors, one principal motion, and restrained high-altitude diffuse light.

## 5.4 Candidate failure tests

- adjectives without scale evidence;
- overview camera replacing requested low-angle distance;
- flat city with no five-role depth;
- people enlarged into portrait subjects;
- gray fog used as empty space;
- structure covered by ornament before load logic is legible;
- global orange-gold or neon contamination;
- derivative variants that only recolor one composition;
- route mixing that produces both calm canon and oppressive megastructure without hierarchy.
